# Python TCP 端口扫描器

用 Python 标准库实现的命令行 TCP 端口扫描器：给定主机和端口范围，并发探测哪些端口处于开放状态。

## 功能

- 扫描指定主机上任意范围的 TCP 端口，输出开放端口列表
- 用线程池并发探测，1024 个端口约 2-3 秒完成
- 支持自定义连接超时和并发数，适配不同网络环境
- 开扫前校验参数：端口越界、起止填反、主机名无法解析都会明确报错退出
- 纯标准库实现，无需安装任何第三方依赖

## 用法

运行环境：Python 3.12（标准库 `socket`、`argparse`、`concurrent.futures`，无第三方依赖）。

### 基本用法

```bash
python scanner.py <host> <起始端口> <结束端口>
```

扫描本机 130-140 端口：

```bash
python scanner.py 127.0.0.1 130 140
```

```
Scanning ports 130 to 140 on host 127.0.0.1...
Open ports: [135]
Time taken: 0.51 seconds
Total open ports: 1
```

### 完整参数

```bash
python scanner.py [-h] [-t TIMEOUT] [-w WORKERS] host start_port end_port
```

| 参数 | 说明 | 默认值 |
| --- | --- | --- |
| `host` | 目标主机，可以是 IP 或域名 | 必填 |
| `start_port` | 起始端口（1-65535） | 必填 |
| `end_port` | 结束端口（1-65535） | 必填 |
| `-t, --timeout` | 单个连接的超时时间（秒） | 0.5 |
| `-w, --workers` | 并发线程数 | 200 |

### 扫描 1-1024 端口

```bash
python scanner.py localhost 1 1024
```

```
Scanning ports 1 to 1024 on host 127.0.0.1...
Open ports: [135, 445, 902, 912]
Time taken: 3.06 seconds
Total open ports: 4
```

### 调整超时和并发

```bash
python scanner.py 127.0.0.1 1 1024 -t 0.3 -w 200
```

```
Open ports: [135, 445, 902, 912]
Time taken: 1.87 seconds
```

把并发降到 50，同样的 1024 个端口：

```bash
python scanner.py 127.0.0.1 1 1024 -t 0.3 -w 50
```

```
Time taken: 6.51 seconds
```

**并发数从 200 降到 50，耗时从约 1.9 秒涨到约 6.5 秒。** 并发数是影响总耗时的主要因素。

> 本文所有耗时都是本机（Windows / Python 3.12）实测一次的结果，会随机器负载和网络状况波动，量级比具体数字更重要。

### 错误输入的处理

```bash
python scanner.py no-such-host.invalid 1 100
# 无法解析主机名: no-such-host.invalid        （退出码 1）

python scanner.py 127.0.0.1 1 70000
# 结束端口必须在1到65535之间                 （退出码 1）

python scanner.py 127.0.0.1 100 50
# 起始端口不能大于结束端口                   （退出码 1）
```

## 工作原理

- **用 `connect_ex()` 而不是 `connect()`**：`connect()` 失败时抛异常，`connect_ex()` 返回错误码，`0` 表示连接成功。扫描器要"把失败当正常结果处理"，返回码比异常更省事。
- **必须设超时**：不设的话，`connect_ex()` 遇到不响应的主机会一直等到操作系统默认超时（几十秒）。设了 0.5 秒，单个端口最坏情况就是 0.5 秒，总耗时才可控。
- **用线程池而不是逐个扫**：端口探测是 I/O 等待，等待期间线程不占 CPU，可以同时发起上百个连接。实测并发 200 扫 1024 端口约 1.9 秒，并发 50 约 6.5 秒。
- **主机名只在入口解析一次**：`socket.gethostbyname()` 把域名换成 IP，之后所有线程都用这个 IP。如果解析失败，直接报错退出，不开线程池。这样 DNS 查询从 N 次变成 1 次，也避免了"每个线程都失败、失败被吞掉、最后输出一个空的端口列表骗人"。
- **校验和解析都在开扫之前完成**：能在入口发现的错误，不留到出口处理。

## 已知限制

- **开着 VPN 或代理时结果会失真**：流量可能被劫持到代理，导致本来没开的端口显示开放（扫本机 `127.0.0.1` 不受影响）。
- **Windows 上未开放端口的耗时接近 `timeout`**：Windows 对未开放端口不返回 RST，连接要等超时才算失败；Linux 会立刻返回。同样参数在 Linux 上会明显更快。
- **并发数不是越大越好**：线程创建和调度有开销，超过机器能承受的并发后反而变慢。200 在这台机器上合适，换机器需要重新试。
- **只支持 TCP**：UDP 端口探测原理不同（没有连接的概念），本项目没做。
- **未测试 IPv6**：`gethostbyname()` 只返回 IPv4 地址。
- **扫描结果不代表服务种类**：它只回答"端口开没开"，不识别上面跑的是什么服务。
